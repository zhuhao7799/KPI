# 高校绩效考核平台业务流程与功能映射

## 1. 文档目的

本文统一业务流程、系统功能、数据关系和验收规则，作为后续数据库、后端、前端和菜单权限开发的依据。

## 2. 核心业务关系

```text
指标体系
   ↓ 发布指标版本
绩效方案（学院/职能部门）
   ↓ 绑定到考核周期
考核周期
   ↓ 根据部门类别自动匹配方案
部门填报 → 材料提交 → 审核 → 复核 → 结果归档
```

一个填报结果必须同时绑定：

```text
考核周期 + 组织单位 + 绩效方案 + 指标版本
```

## 3. 业务角色

| 角色 | 主要职责 |
|---|---|
| 系统管理员 | 用户、部门、角色、菜单和系统参数 |
| 考核办管理员 | 周期、指标、方案、发布、任务监控 |
| 部门填报员 | 指标自评、材料上传、提交和补正 |
| 审核人 | 查看材料、评分、退回、审核通过 |
| 复核人 | 结果复核、确认和归档 |
| 学校领导 | 查看授权范围内的汇总、排名和报告 |

## 4. 标准业务流程

### 4.1 基础配置

1. 维护学校组织机构。
2. 导入学院和职能部门。
3. 创建用户并绑定部门、岗位和角色。
4. 配置角色菜单、按钮和数据范围。

### 4.2 指标体系配置

1. 创建指标版本草稿。
2. 新增、编辑和删除指标项。
3. 设置指标权重、满分和评分公式。
4. 校验指标权重合计为 100%。
5. 发布指标版本。
6. 已发布版本进入只读状态。

### 4.3 绩效方案配置

1. 创建学院方案和职能部门方案。
2. 配置方案指标项和分类权重。
3. 校验方案权重合计为 100%。
4. 发布方案。
5. 已发布方案进入只读状态。

### 4.4 考核周期配置

1. 创建年度考核周期。
2. 导入或生成组织单位快照。
3. 绑定指标版本。
4. 绑定学院绩效方案。
5. 绑定职能部门绩效方案。
6. 校验周期配置完整性。
7. 发布周期并开放填报。
8. 锁定周期配置。

### 4.5 单位填报

1. 用户登录系统。
2. 系统根据用户数据权限获取可填报单位。
3. 后端根据考核周期和单位类别自动匹配绩效方案。
4. 后端返回方案指标快照。
5. 用户填写自评、说明和工作总结。
6. 按指标上传佐证材料。
7. 保存草稿。
8. 提交审核。

前端不得自行指定任意指标版本，方案和指标版本由后端根据周期及单位自动确定。

### 4.6 审核与结果

1. 考核办分派审核任务。
2. 审核人查看填报和材料。
3. 审核人评分、填写意见或退回补正。
4. 部门修改后重新提交。
5. 审核通过后进入复核。
6. 复核人确认最终结果。
7. 系统生成得分、等级和排名。
8. 发布结果并归档。

## 5. 状态规则

### 5.1 指标版本

```text
DRAFT → PUBLISHED → LOCKED → ARCHIVED
```

### 5.2 绩效方案

```text
DRAFT → PUBLISHED → LOCKED → ARCHIVED
```

### 5.3 考核周期

```text
DRAFT → CONFIGURING → PUBLISHED → FILLING → REVIEWING → CLOSED → ARCHIVED
```

### 5.4 填报记录

```text
DRAFT → SUBMITTED → RETURNED → SUBMITTED
                    ↓
                 CONFIRMED → ARCHIVED
```

## 6. 数据模型关系

```text
indicator_version
        ↓
performance_scheme
        ↓
assessment_cycle_scheme
        ↓
assessment_cycle
        ↓
organization_unit_snapshot
        ↓
assessment_submission
        ↓
assessment_score_detail
```

周期方案绑定表 `assessment_cycle_scheme` 必须包含：

| 字段 | 说明 |
|---|---|
| assessment_cycle_id | 考核周期 |
| organization_category | 二级学院、职能部门等 |
| scheme_id | 绩效方案 |
| indicator_version_id | 指标版本 |
| status | 绑定状态 |

唯一约束：

```text
assessment_cycle_id + organization_category
```

## 7. 功能与接口映射

| 功能 | 后端接口 | 前端页面 |
|---|---|---|
| 指标版本 | `/kpi/indicator-versions` | 指标体系管理 |
| 绩效方案 | `/kpi/schemes` | 绩效方案管理 |
| 周期管理 | `/kpi/cycles` | 考核周期管理 |
| 周期方案绑定 | `/kpi/cycles/{code}/schemes` | 周期方案配置 |
| 填报上下文 | `/kpi/filling/context` | 单位绩效填报 |
| 提交审核 | `/kpi/submissions` | 单位绩效填报 |
| 审核待办 | `/kpi/tasks` | 绩效审核 |
| 结果查询 | `/kpi/results` | 绩效结果查询 |

## 8. 发布前校验

考核周期发布前必须满足：

- 周期日期有效。
- 至少存在一个组织单位快照。
- 指标版本状态为 `PUBLISHED`。
- 学院方案已绑定。
- 职能部门方案已绑定。
- 所有方案权重合计为 100%。
- 方案中的指标均存在于指标版本或方案快照中。

## 9. 当前实现差距

当前已具备指标、方案、周期的基础页面和部分接口，但还需要完成：

1. `assessment_cycle_scheme` 周期方案绑定表。
2. 周期与指标版本正式绑定。
3. 周期与组织类别方案绑定。
4. 填报上下文自动匹配方案。
5. 提交记录保存方案和指标快照。
6. 方案和周期发布前完整校验。
7. 统计、导出和消息提醒。

在上述功能完成前，系统只能视为基础演示闭环，不能视为完整生产流程。

## 10. 验收场景

```text
创建 2026 周期
→ 导入部门
→ 发布 2026-v1 指标版本
→ 创建学院和职能部门方案
→ 绑定周期方案
→ 发布周期
→ 学院用户自动加载学院方案
→ 完成填报和材料上传
→ 审核、退回、重新提交
→ 复核确认
→ 生成排名并归档
```
