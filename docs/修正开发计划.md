# 高校绩效考核系统修正开发计划

## 1. 修正目标

将当前“指标、方案、周期相对独立”的基础闭环，修正为：

```text
指标体系 → 绩效方案 → 考核周期绑定 → 部门自动匹配 → 填报 → 审核 → 结果归档
```

所有提交记录必须保存考核周期、组织单位、绩效方案和指标版本快照，确保历史结果不受后续配置变化影响。

## 2. 开发原则

- 数据库、后端、前端、菜单权限同步开发。
- 先完成数据关系，再开发操作页面。
- 已发布或已使用的数据不可直接修改。
- 后端负责方案和指标版本匹配，前端不能自行指定版本。
- 每个阶段形成可编译、可联调、可验收成果。

## 3. 阶段计划

### 阶段一：数据模型修正

**目标：建立周期、方案、指标版本的正式关系。**

数据库交付：

- 新增 `assessment_cycle_scheme` 周期方案绑定表。
- `assessment_submission` 增加 `scheme_id`。
- 增加周期、方案、指标版本外键和唯一约束。
- 增加发布状态和锁定时间字段。
- 增加历史快照字段。
- 编写 V9 迁移脚本。

验收条件：

- 一个周期可以绑定学院方案和职能部门方案。
- 一个周期和组织类别只能有一个有效方案。
- 已发布周期不能修改绑定关系。

### 阶段二：指标体系完整 CRUD

后端：

- 版本列表、新增、编辑、删除、复制。
- 指标项新增、编辑、删除、排序。
- 发布、撤回、锁定。
- 权重合计 100% 校验。
- 已使用版本禁止删除。

前端：

- 版本列表页。
- 版本编辑页。
- 指标项编辑表格。
- 权重实时统计。
- 发布和锁定确认。

菜单权限：

```text
kpi:indicator:list
kpi:indicator:add
kpi:indicator:edit
kpi:indicator:remove
kpi:indicator:publish
kpi:indicator:lock
kpi:indicator:copy
```

### 阶段三：绩效方案完整 CRUD

后端：

- 方案新增、查询、编辑、删除、复制。
- 方案指标项增删改查。
- 学院、职能部门分类。
- 方案权重合计校验。
- 方案发布、锁定、归档。
- 已被周期使用的方案禁止删除。

前端：

- 方案列表。
- 方案编辑。
- 指标配置表格。
- 组织类别选择。
- 权重校验和发布状态。

菜单权限：

```text
kpi:scheme:list
kpi:scheme:add
kpi:scheme:edit
kpi:scheme:remove
kpi:scheme:indicator
kpi:scheme:publish
kpi:scheme:lock
```

### 阶段四：考核周期完整管理

后端：

- 周期新增、编辑、查询。
- 部门快照导入和替换。
- 指标版本绑定。
- 学院方案绑定。
- 职能部门方案绑定。
- 发布前完整性校验。
- 发布、开放填报、关闭填报、归档。

前端：

- 周期列表。
- 周期基本信息表单。
- 参与部门管理。
- 指标版本选择。
- 分类方案绑定。
- 发布校验结果展示。

### 阶段五：填报上下文改造

新增接口：

```text
GET /kpi/filling/context?cycleCode={cycle}&unitId={unit}
```

后端根据周期和部门类别自动返回：

```text
周期
部门
部门类别
绩效方案
指标版本
指标项快照
```

改造要求：

- 前端不再自由传入指标版本。
- 后端自动匹配方案和指标版本。
- 提交时保存方案和指标快照。
- 评分、审核、结果统一使用快照。

### 阶段六：权限和菜单联调

配置：

- 绩效管理目录。
- 指标体系管理菜单。
- 绩效方案管理菜单。
- 考核周期管理菜单。
- 填报、审核、结果菜单。
- 新增、编辑、删除、发布、锁定按钮。

数据权限：

| 角色 | 数据范围 |
|---|---|
| 系统管理员 | 全部数据 |
| 考核办管理员 | 全校考核数据 |
| 部门填报员 | 本部门数据 |
| 审核人 | 被分配部门 |
| 学校领导 | 授权查看范围 |

### 阶段七：流程联调与验收

完整验收路径：

```text
创建指标版本
→ 发布指标版本
→ 创建学院方案
→ 创建职能部门方案
→ 配置方案指标
→ 创建考核周期
→ 绑定指标版本和方案
→ 导入部门快照
→ 发布周期
→ 部门自动匹配方案
→ 填报和上传材料
→ 提交审核
→ 退回修改
→ 重新提交
→ 审核确认
→ 结果查询和归档
```

## 4. 交付顺序

```text
V9 数据迁移
  ↓
指标体系 CRUD
  ↓
绩效方案 CRUD
  ↓
周期方案绑定
  ↓
填报上下文自动匹配
  ↓
菜单和数据权限
  ↓
全流程联调
```

## 5. 阶段完成标准

每个阶段必须同时满足：

- 数据库迁移可重复执行。
- 后端接口有权限校验。
- 前端页面可操作。
- 菜单和按钮权限已配置。
- 正常、异常、越权场景均有处理。
- Windows Maven 编译通过。
- 关键接口完成实际请求验证。

## 6. 当前优先级

| 优先级 | 工作项 | 原因 |
|---:|---|---|
| 1 | 周期方案绑定表 | 修复核心业务关系缺口 |
| 2 | 填报自动匹配方案 | 防止前端越权指定指标 |
| 3 | 提交快照完善 | 保证历史结果稳定 |
| 4 | 指标和方案状态锁定 | 保证发布后不可篡改 |
| 5 | 菜单和数据权限 | 支撑不同角色实际使用 |
| 6 | 全流程回归 | 验证业务闭环一致性 |

## 7. 预期结果

完成本计划后，系统能够按以下规则运行：

```text
考核办配置一次
部门按授权自动获得对应方案
填报和评分使用统一快照
审核和结果沿用同一业务版本
历史年度数据可追溯、不可篡改
```
