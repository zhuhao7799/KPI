# 身份、权限与数据范围

RuoYi-Vue-Plus 负责登录态、通用菜单权限和用户基础组织信息。绩效模块不复制账号表，也不将高校部门名称作为授权主键。

请求进入绩效接口时，适配层使用 `LoginHelper.getUserIdStr()` 取得已登录用户 ID，再通过 `kpi_user_role_binding` 解析生效的绩效角色。角色仅决定能否执行某类业务动作；需要访问具体考核对象时，再校验 `kpi_scope_grant`。

| 业务角色 | 允许动作 | 数据范围 |
| --- | --- | --- |
| 校级系统管理员 | 全部 | 全周期、全单位 |
| 考核办 | 周期、指标、审核、确认、归档、结果 | 全周期、全单位 |
| 单位填报人 | 填报、查看本单位结果 | 显式授权的周期和单位 |
| 审核人 / 评委 | 审核、查看材料与结果 | 显式授权的周期和单位 |
| 结果查询人 | 查询结果 | 显式授权的周期和单位 |

授权以周期快照和外部单位 ID 为条件，避免机构改名、合并或重组影响已发布考核历史。范围授权可设置失效时间；失效后即时拒绝访问。

`KpiScopeAuthorizationService` 是接口层调用的唯一业务数据范围入口：先检查角色权限，再检查范围。校级系统管理员和考核办拥有业务全局范围，其余角色必须有有效授权记录。

RuoYi 集成位于 `backend/kpi-ruoyi-adapter`：`KpiCurrentActor` 通过 `LoginHelper` 读取当前会话，`KpiRuoYiConfiguration` 使用 RuoYi 配置的数据源创建身份和范围适配器。这样，控制器不接受用户 ID 或角色作为请求参数。

首次部署时，由数据库管理员核实指定 RuoYi 账号后运行 `bash deploy/bootstrap-kpi-admin.sh <用户名>`，建立首个校级管理员绑定。后续通过 `/kpi/security/roles` 与 `/kpi/security/scopes` 授予或撤销业务角色和周期/单位范围；这两个接口只允许校级管理员使用。脚本不会自动给 RuoYi 示例账号授权。
