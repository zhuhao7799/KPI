# 绩效权限与数据范围模型

角色不从组织树推导。用户角色、可操作周期和可操作单位分别授权，避免“部门管理员”天然拥有全部考核材料。

| 角色 | 主要权限 |
| --- | --- |
| 校级系统管理员 | 平台管理及全部业务权限 |
| 考核办 | 周期、指标版本、审核确认、归档和结果管理 |
| 单位填报人 | 在获授单位范围内创建和修改未提交材料 |
| 审核人/评委 | 按获授任务审核，读取所需证据 |
| 结果查询人 | 仅查看获授权结果 |

系统授权检查分为两层：先判定业务角色是否具备动作权限，再判定 `kpi_scope_grant` 是否覆盖当前周期和单位。RuoYi 的 `sys_user_role`/`sys_role` 是角色解析主来源，`kpi_user_role_binding` 只补充时间限定的绩效角色授权。Evidence 访问还必须关联具体提交和指标，不能只依赖文件对象标识。
