# 第一阶段边界

## 目标

建立可扩展的高校组织绩效领域模型，使年度考核能在制度调整后仍按当年版本复算。

## 本阶段已实现

| 能力 | 处理方式 |
| --- | --- |
| 考核对象 | 以 `OrganizationUnit` 表示学院、职能部门等单位，分类为开放枚举字符串，避免把学校组织结构写死。 |
| 考核周期 | `AssessmentCycle` 使用开始日、结束日和状态，校验日期边界。 |
| 指标版本 | `IndicatorVersion` 为不可变快照，包含编码、名称、权重和每项满分。 |
| 评分证据 | `EvidenceReference` 只保存受控对象标识与摘要；不保存公开下载地址。 |
| 结果计算 | `ScoreCalculator` 校验缺失评分、重复评分、范围和权重，生成明细与总分。 |
| 审计 | `AuditEvent` 保存结果生成事件及参与主体。 |
| 持久化边界 | `kpi-storage` 提供 MySQL 8 基线迁移，定义周期、组织快照、指标快照、提交、明细、审计和 Outbox。 |

## 明确不在本阶段的能力

- 学校指标模板、实际评分公式、排名和一票否决规则；
- 真实材料上传、用户认证、数据权限和外部消息；
- 审批页面及工作流定义；
- 数据库持久化和迁移脚本。

这些能力须在制度负责人确认规则后建立，并将规则版本、组织快照和计算参数一并冻结。

## 集成约束

1. 每次提交评分都必须携带考核周期、单位、指标版本和规则版本。
2. Evidence 只能由服务端按授权生成临时访问，不得把通用文件下载链接存入结果。
3. 工作流只驱动状态转换；评分计算以已冻结快照为输入，不从活动配置读取权重。
4. 通知、导出和跨服务同步通过 Outbox 事件实现幂等重试。
