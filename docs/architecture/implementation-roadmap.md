# 实施路线与质量门槛

## 已完成：S1 评分预览

输入虚构的两项评分，服务端按冻结版本计算并返回结果明细。验收脚本覆盖健康检查、页面资源、正常计算与异常分数拒绝。

## 正在推进：S2 考核配置与提交快照

1. 引入 `AssessmentSubmission` 聚合，保存周期、单位、指标版本、评分明细与提交状态；
2. 为每次提交生成不可变 `calculationContext`，包括精度、公式版本与组织快照；
3. 以数据库迁移脚本创建表结构，并为审计事件建立追加式记录；
4. 接口必须拒绝活动指标版本被直接覆盖或已归档结果被重算。
5. 提交和状态流转在服务端执行角色及周期/单位范围授权。

**验收门槛**：同一提交在规则配置改变后，仍可按保存的快照得到相同结果；错误版本、重复提交和越权访问均被拒绝。

## 后续：S3 审批与证据

1. 评估并接入可运行的 RuoYi-Vue-Plus/WarmFlow；
2. 目标申报、过程填报、审核、退回、确认和归档使用明确业务状态；
3. Evidence 服务使用对象标识、授权校验和短期签名地址，禁止通用文件下载；
4. 业务状态变更、消息和导出经 Outbox 处理，带幂等键与重试记录。

**验收门槛**：审批服务重启后待办不丢失；无权限用户不能读取材料；失败通知可重试且不重复。

## 后续：S4 学校规则与上线准备

1. 导入并核对学院、职能部门与考核分组，组织层级与考核分组分开维护；
2. 配置校方确认的指标、权重、扣分、一票否决、排名、申诉和公示规则；
3. 完成数据迁移演练、审计导出、备份恢复、性能测试和试运行；
4. 对真实材料、账号、角色和运行环境进行上线验收。

**验收门槛**：制度负责人签署规则版本；可复算样本与线下结果一致；安全、备份和权限验收通过。
